Audit Report — Anonymized Case Study

This audit was conducted using natural-joints — independent code & data audits of published research papers.

Anonymized: a 2025 study reporting spatial multi-omics signatures that predict checkpoint-immunotherapy outcomes in a solid tumour.

Anonymization note. Identifying details have been removed: authors, journal, DOI/PMID/accession IDs, the code-repository and data-deposit locations, the specific institutions and cohort names, the tumour type, drug brand names, exact file paths, and patient identifiers. Cohorts are de-identified as Discovery (A) (the training cohort), Validation‑B, and Validation‑C. The two checkpoint agents are ICI‑A (a first-line anti‑PD‑1 monotherapy) and ICI‑B (a second anti‑PD‑1 agent). Column names, numeric values, and code constructs are otherwise reproduced faithfully so the technical findings remain checkable in principle. This version is a methodology case study; it names no paper, person, or institution.

Paper: identifiers withheld for anonymization — a 2025 spatial multi-omics immunotherapy-signature study in a high-impact genetics journal.
Code & data: a public code repository plus a public data deposit (locations withheld).
Audit date: 2026-06-01.

Scope. This report describes technical observations about the public materials associated with the study — the manuscript text, the released code repository, and the deposited data files. It does not evaluate restricted clinical data the authors may hold privately, the underlying patient records, or any laboratory practice. Where the released code, the deposited data, and the manuscript text are inconsistent with each other, the inconsistency is described.

What this report is not. No allegation of scientific misconduct, fraud, fabrication, intentional misrepresentation, or professional negligence is made or implied. Coding errors, missing files, and data-formatting inconsistencies are common in research code; the patterns described here (e.g., the Surv(as.numeric(time, event)) typo) have appeared in many widely-used codebases without any implication of bad intent. The report is an opinion-based technical commentary on public artifacts, in the tradition of post-publication peer review.

Possible reconciliations. Some findings might be resolvable by private data, scripts, or analyses not included in the public deposit. Where that is plausible, the report flags it. The findings stand only against what is publicly available; the underlying scientific question of whether the signatures predict outcomes in this indication is independent of the artifact-level discrepancies described here and may be resolved by future work.

Reproducibility. Every observation in this report is reproducible from the public data deposit + the public code repository + the manuscript text. No access to restricted clinical data was used at any point.

Right of reply. The authors and their institutions are invited to respond. Corrections, clarifications, additional context, or pointers to private materials that resolve any of the observations will be incorporated and credited. Contact via www.natural-joints.com.

Headline finding. A high-impact study claims to predict 2-year PFS in solid-tumour immunotherapy. The training-cohort data says "2 years" is actually 1.45 years.

Paper claims affected:
  • Discovery HRs (tumour 3.8, p=0.004; stroma 0.4, p=0.019) → collapse to non-significance under correction of a one-character R typo that drops the censoring vector (HR 2.2, p=0.11 and HR 0.30, p=0.057)
  • Validation-B HRs (tumour p=0.05, stroma p=0.036, both 1-sided) → both p-values exceed 0.05 when correctly two-sided (0.10 and 0.072); both 95% CIs cross 1
  • Discovery cell-to-gene HR=5.1, p=0.002 → not reproducible end-to-end; depends on coefficient files missing from the deposit and on circular gene selection (signature picked by held-out test HR)
  • Validation-B cell-to-gene HR=0.38 → the released validation script emits HR=1.1, p=0.6 instead
  • Validation-C HRs (resistance 1.7, response 0.56) → unverifiable; zero code, zero data in the repo
  • "Predicts PFS at 2 years" (the immunotherapy field's durable-benefit milestone) → the Discovery tumour "2 years" is 1.45 real years, so the signature is predicting 17-month PFS, an endpoint that doesn't appear in the clinical literature
  • "Signatures identify subgroups outperforming standard-of-care monotherapy" → 37%-stretched time axis on every Discovery tumour figure; apparent outperformance of the ~10-month benchmark collapses to matching it

The spotlight bug: PFS_2Years_months isn't months

The study deposits a Discovery-cohort tumour CSV with two columns describing time-to-progression: PFS_Days (days from treatment to progression) and PFS_2Years_months (the same time in months, capped at 24).

Compute the implied days-per-month in the file:

mean(PFS_Days / PFS_2Years_months) = 22.11

A real month is 30.44 days (365.25 ÷ 12). The column labeled "months" doesn't hold months — it holds days/22.11. The "2-year cap" at 24 fires at 24 × 22.11 = 530.6 real days = 17.4 real months ≈ 1.45 years.

The paired stroma file uses the standard 30.44 divisor. Same patients, identical PFS_Days across both files; only the Discovery tumour file's _months column appears to use a non-standard divisor. The Methods section says twice: "PFS data (time in months and an event indicator)." In the Discovery tumour file, the _months column does not match that description.

The finding's impact

The paper's scientific contribution rests on one claim: the responder signature picks out patient subgroups that outperform standard-of-care immunotherapy — i.e., do better than the ~10-month median PFS of first-line anti-PD-1 monotherapy in this indication.

The bug stretches every Discovery tumour survival time by 37%. Any responder-subgroup median that reads as 12–14 months on the figure is really 8.7–10.2 real months — at or below the standard-of-care benchmark, not above it.

What looked like "the signature identifies durable responders who outperform standard care" becomes "the signature identifies patients who do what monotherapy patients already do." A subgroup that just matches standard of care is not a clinical contribution.

The Cox HR itself doesn't move (scale-invariant) — the signature still ranks patients. The clinical narrative — "we identify subgroups that beat standard care" — collapses to "we identify subgroups that match it."

And the headline endpoint itself is mislabeled: the paper claims "PFS at 2 years," the immunotherapy field's durable-benefit milestone. The Discovery tumour "2 years" is 1.45 real years. So the signature isn't predicting 2-year PFS at all — it's predicting 17-month PFS, an endpoint that doesn't appear in the clinical literature.

Downstream effects on the Discovery tumour analyses:

  • PFS_2Years_Index — the binary "event by 2 years" flag — is thresholded from this corrupted column. Patients with real events in days 531–730 (between 17.4 and 24 real months) are at risk of being labeled "no event by 2 years" despite progressing before 2 real years.
  • LASSO feature selection is trained against this potentially-mislabeled outcome.
  • Reported Discovery tumour Cox HRs use Surv(_months, _Index).
  • Every Discovery tumour Kaplan-Meier figure plots survival on an x-axis labeled "PFS-2Year (months)" — on the 37%-stretched timescale.
  • The "5-year PFS" landmark in this file is 60 × 22.11 days = 3.6 real years, not 5.

Bugs in the committed code

Surv(as.numeric(time, event)) typo at 11+ sites MAJOR

as.numeric() silently drops extra positional arguments, so the event vector is discarded before Surv() ever sees it; Surv(time) with one argument defaults to "all events observed."

library(survival)
t <- c(10, 20, 30, 40, 50)
e <- c(1,  0,  1,  0,  1)
Surv(as.numeric(t, e))   # 10  20  30  40  50      <-- all events observed
Surv(t, e)               # 10  20+ 30  40+ 50      <-- 20 and 40 censored

The typo appears in the tumour and stroma cell-fraction LASSO scripts plus 11 sites across the RNA-LASSO scripts. This single bug collapses both Discovery headline HRs: Discovery tumour resistance HR 3.8 (p=0.004) → 2.58 (p=0.053); Discovery stroma response HR 0.4 (p=0.019) → 0.30 (p=0.057). Both 95% CIs cross 1.

BH/FDR correction commented out across all 4 RNA-LASSO scripts MAJOR

In the RNA train/test scripts:

#FDR <- p.adjust(response$table$PValue, method="BH")
FDR <- response$table$PValue
...
dex_sel_genes = dex_df[which(dex_df$FDR < 0.05),] # take only genes that have FDR < 0.1

The variable named FDR holds the raw edgeR exactTest p-value. The trailing comment also doesn't match the literal threshold. With 6,000–10,000 genes per split gated on raw p < 0.05, ~5% of the genome enters LASSO on chance alone — ~500× more false positives than the paper's "FDR < 0.05" claim implies.

Orphan coefficient files MAJOR

The final-signature RNA script writes final_coeffs_PFS_5Years_3celltypes_CW_resistance.csv at one line and reads final_coeffs_PFS_5Years_3celltypes_resistance_0p1.csv (a different filename) a few lines later. A repository-wide search returns zero matches for the read filename. The same pattern affects the training-cohort definition file and every held-out-HR (hzrs_*.csv) file. The released code cannot regenerate the published cell-to-gene HRs end-to-end.

Cell-typing per-cell z-score destroys marker discrimination MAJOR

In the cell-typing notebook, each expression matrix is z-scored per cell across markers (axis=1), then hardcoded M1 vs M2 gates are applied on those z-scored values at boundary 0.3. Per-cell z-scoring forces every cell to mean-0/SD-1 across its panel — a CD8 cell with high CD8 looks identical to a tumour cell with high pan-CK because both peak in one channel of their normalized panel. Affects all cell labels → cell-fraction features → headline HRs.

Cell-typing ffill priority mislabels Tregs as Proliferating_Tumour MODERATE

The cell-label priority chain: ki67cell > mac_types > gzmbcell > pd1cell > foxp3cell > CD4_types > CT_1. A Ki67+ FOXP3+ CD4 cell (a proliferating Treg) gets labeled Proliferating_Tumour — the lead cell type in the resistance signature. Un-subtyped macrophages default to M1_mac, biasing the M1/M2 ratio toward M1.

Multi-image patient replicates fed to coxph without cluster(Patient_ID) MODERATE

Discovery: 3 patients with 2 images each. Validation-B: 7 patients with 2–3 images each. Replicate cores per patient are fed to coxph as if they were independent observations. Standard errors are too narrow; p-values are too small by ≈10–15%.

Tumour LASSO drops Unidentified + Stroma cell-type columns MODERATE

The slice cellFrac[,c(38:51)] selects 14 cell-type columns but skips Unidentified and Stroma. Row-sums range 0.37–1.0 instead of summing to 1.0. Un-normalized cell-fractions are fed to unstandardized LASSO, biasing feature selection toward features that correlate with how much "non-included" tissue each patient has.

CD8 lineage triple-counted in LASSO MODERATE

CD8_cells, Exhausted CD8, and Cytotoxic CD8 all enter the LASSO design matrix as separate features. Numerically, CD8_cells ≠ Exhausted CD8 + Cytotoxic CD8 (max difference 0.23). The same cells are partially counted across three columns and contribute three independent feature slots, destabilizing selection.

Hardcoded integer column indices in marker-correlation loop MODERATE

The protein/UMAP script uses expr[,21], expr[,25], expr[,43] for "pdl1", "cd163", "pck" in a correlation loop. A safer pattern (which(colnames(expr) == "PD-L1")) exists in the same file but isn't used here. Any reordering of data.X upstream silently swaps which markers are correlated.

Bugs in the deposited data

PFS_2Years_months = days/22.11 in Discovery tumour file MAJOR

Covered in the spotlight section above. The Discovery tumour file's months column is on a 22.11-day-per-unit scale; the paired stroma file is correct at 30.44. 37% time-axis stretch on every Discovery tumour figure; "2-year" landmark = 1.45 real years; potential mislabeling of PFS_2Years_Index for patients with events in days 531–730.

Censored ≡ Status ≡ Current Status ≡ OS MODERATE

All three columns are 100% collinear with overall survival in the deposited CSVs:

  • Alive ↔ Censored ↔ Status = 0
  • Deceased ↔ Uncensored ↔ Status = 1

There is no PFS-specific censoring information in these three columns. PFS censoring exists only in the PFS_*Index columns. Any script that pulls a censoring vector from Status silently substitutes OS for PFS.

Discovery cohort is n=29–31 unique patients, not n=41 MODERATE

The cell-fraction CSVs contain 32–33 images. After de-duplicating on Patient_ID, the unique-patient count is 29–31 (3 patients are double-imaged). The abstract claims n=41. The (HR, p) values aren't affected — they're computed on n=32 images — but the sample-size claim is materially overstated.

Same patient has different drug across paired files MINOR

One patient's core: ImmunoTx = ICI-B in the stroma file, = ICI-A in the tumour file. Same patient, same image, two files, two drugs.

Same patient has different histology across paired files MINOR

Three of one patient's images: Histology.1 = Adenocarcinoma in the stroma file, = Adenosquamous in the tumour file. Same images, two histology labels.

line_at_ITX categorical encoding split by TMA MODERATE

One TMA batch uses integer "1" for first-line therapy. The other batch uses string "1st line". Biopsy_at_ITX is missing for the entire second batch, making it a perfect cohort indicator masquerading as a biology variable.

Patient vital-status flips across duplicate cores MINOR

One patient is coded simultaneously Deceased and Alive across duplicate cores at the same OS_Days=137. A second patient has the same flip. A third patient has Response flipping between Responder and Non-responder across 3 cores. These affect ≤2 patients in a 29-patient Discovery cohort but reveal cores were not de-duplicated before label assignment.

Cross-file row-count and ID drift MINOR

The tumour file has 67 rows; the stroma file has 68. Five image IDs are unique to one or the other. The Validation-B CK vs stroma cohorts overlap on only 21 of 30/27 patient IDs. PFS_5Years_months disagrees at the second decimal across shared rows (1.80 vs 1.84). Cross-cohort exact-match joins fail silently.

Inconsistent free-text histology labels MINOR

The Histology column contains Squamous vs squamous cell carcinoma vs Squamous cell carcinoma, plus one label with an embedded newline (\n) in the middle. Any filter or grouping on this column produces inconsistent cohorts depending on which spelling is matched.

Choices that overstate the significance

Cell-to-gene signatures selected by held-out test-cohort HR MAJOR

In the final-signature RNA script:

hzrs = read.csv("hzrs_..._resistance_..._genes.csv")
good_models = which((hzrs$x) >= 1.5)         # resistance direction
# mirror in stroma response script:
good_models = which((hzrs$x) <= 0.7)         # response direction

hzrs$x is the held-out test-cohort HR from 50 random 80/20 splits. The final signature is built by running gene voting only over splits whose test HR was already in the desired direction. The validation result is the model-selection criterion — a circular validation pattern. Genes appearing across these "good" splits are then assembled and re-evaluated on the same Discovery cohort.

Validation-B p-values halved 1-sided post-hoc MAJOR

In 4 validation scripts:

p_value_one_sided <- ifelse(summary(cox)$coefficients[2] > 1,
                            p_value_two_sided / 2,
                            1 - p_value_two_sided / 2)

Direction is picked post-hoc from the sign of the observed coefficient. Plots annotate this with "Log-Rank-1-sided" for validation and "Log-Rank-2-sided" for discovery. Both abstract validation p-values become two-sided 0.10 (Validation-B tumour) and 0.072 (Validation-B stroma) — neither below conventional significance, both 95% CIs cross 1.

Tumour and stroma analyses share 28+ patients — not 8 independent tests MAJOR

Discovery tumour (29 patients) ∩ Discovery stroma (31 patients) = 28 in common. Validation-B tumour (26) ∩ Validation-B stroma (26) = 26 (full overlap). The 4 cell-type HRs + 4 cell-to-gene HRs the abstract presents as "8 consistent results" are not 8 independent tests — most are recomputations on substantially the same patients with different feature transformations. Bonferroni at family size 8 (α=0.0062) drops every reported p-value except Discovery tumour (0.004) and Discovery cell-to-gene resistance (0.002) below significance — and both survivors are in-sample LASSO refits.

lower.limits=0 / upper.limits=0 forces directional signatures MAJOR

The LASSO sign constraint lower.limits = 0 (tumour) and upper.limits = 0 (stroma) guarantees the resulting signature is non-negative ("resistance") or non-positive ("response") — direction is set by a keyword, not by the data. Post-LASSO refit then silently drops coefficients via coeffs = coeffs[which(coeffs >= 2)] (HR ≥ 7.4 per unit fraction), a hardcoded filter with no rationale. With correct Surv + sign constraint, the Discovery tumour signature gives HR=2.18, p=0.105. Without sign constraint, no cell type meets the stability threshold.

Cohort-comparability gap: Discovery = 1st-line pre-Tx ICI-A; Validation-B = post-1st-line ICI-B MAJOR

Discovery training: all Biopsy_at_ITX = "Pre", all line_at_ITX = "1", 28/32 on ICI-A. Validation-B: Biopsy_at_ITX = #N/A for 35/35, 27/35 on ICI-B, 23/35 ≥ 2nd line. Pre-treatment vs post-treatment biopsies are biologically different — clonal selection under immunotherapy. Commented-out filters in the LASSO scripts (Histology %in% c("Squamous"), ImmunoTx %in% c("ICI-B")) indicate that these variables were considered during script development as candidate filters.

No clinical covariate adjustment MODERATE

Final reported HRs are univariate Cox — no age, smoking, histology, line of therapy, drug, or biopsy timing. Standard practice in immunotherapy biomarker studies includes at least line and drug as covariates.

LASSO fit on PFS_5Years, headline HR reported on PFS_2Years MODERATE

Same script. The cell-to-gene pipeline also fits gene selection on PFS_5Years but reports a training HR on OS_5Years — three different endpoints appear in one script. The released materials do not specify which endpoint was pre-registered as the primary.

Data-dependent tertile cutpoint computed on test cohort MINOR

The "tertile" cutpoint for binarizing the signature score is computed from the test cohort's own score distribution — a mild form of test-set leakage where the dichotomization boundary depends on the test data.

Inconsistent LASSO stability thresholds MINOR

Tumour LASSO: 100 random seeds, 50% stability threshold for retaining a feature. Stroma LASSO: 50 seeds, 30% threshold. Different stringency for the two compartments; the manuscript does not give a rationale for the different choices.

Reproducibility gaps

Validation-C cohort entirely absent from the repo MAJOR

A repository-wide search for any Validation-C identifier returns zero matches in any analysis script. The abstract's Validation-C HRs (resistance HR=1.7, response HR=0.56, n=79) are not reproducible from the public artifact. The third "independent" cohort exists only in manuscript text.

Validation-B stroma RNA released code emits HR=1.1, p=0.6 — abstract claims HR=0.38 MAJOR

The stroma-RNA validation script contains the literal label:

label = "HR = 1.1 (0.43-3) \n p = 0.6 (Log-Rank-1-sided) \n cutpoint = tertile"

The script uses Surv(OS_5Years_months, OS_5Years_index) on the Validation-B stroma CSV. Output: HR=1.1, p=0.6. The abstract reports HR=0.38 for the same comparison. The released code does not reproduce the abstract's Validation-B stroma response HR. (A two-sided p of 0.6 is symmetric — this is not a sidedness artifact, the script computes HR=1.1.)

Three deposit files referenced by released code don't exist MAJOR

  • the training-cohort definition file — defines the Discovery training cohort
  • final_coeffs_PFS_5Years_3celltypes_*_resistance_0p1.csv — read by signature scripts (different filename than what gets written)
  • the held-out-HR files (hzrs_*.csv) — held-out test-cohort HRs from 50 train/test splits

The published cell-to-gene HR=5.1 cannot be regenerated from the artifacts the paper points readers to.
