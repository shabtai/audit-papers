Audit Report — Aung et al., Nature Genetics 2025

"Spatial signatures for predicting immunotherapy outcomes using multi-omics in non-small cell lung cancer"

This audit was conducted using natural-joints — independent code & data audits of published research papers, applying semantic data-layer enrichment plus multi-agent code/honesty/facts review to detect findings where the script source, the deposited data, and the paper text are in tension.

Paper: Aung TN, Monkman J, Warrell J, et al. "Spatial signatures for predicting immunotherapy outcomes using multi-omics in non-small cell lung cancer." Nat Genet (2025). 10.1038/s41588-025-02351-7 · PMID 41073787 · PMCID PMC12513832.
Code: tznaung/NSCLC_SpatialOmics (3 stars, 20 commits).
Data: figshare 29944619 (~12 MB) + GEO GSE271689, GSE221733.
Audit date: 2026-06-01.

Headline finding. Two of the Yale-discovery-cohort hazard ratios published in the paper — the resistance signature HR=3.8 (p=0.004) and the response signature HR=0.4 (p=0.019) — collapse to non-significant when an obvious one-character bug in the committed R source is corrected. The same buggy pattern appears 11 times across the cell-fraction analysis scripts. The bug treats every patient as if they had a progression event, regardless of censoring. This is the canonical "the explanation of wrong uploaded data is not very acceptable" case — the bug lives in the R script that is the published reproduction artifact for the paper. The data is fine. The code that processes the data is broken in a way that inflates significance.

CRITICAL: Surv(as.numeric(time, event)) drops the event vector

#1. as.numeric() silently discards the censoring indicator; Surv() defaults to "all events observed" CRITICAL CODE

Buggy pattern:

y_df = Surv(as.numeric(cellFrac$PFS_5Years_months, cellFrac$PFS_5Years_Index))

What this does in R:

  1. R's as.numeric() accepts one argument; additional positional arguments are silently dropped. So as.numeric(time, event) evaluates to as.numeric(time) — the event-status column is discarded before Surv() ever sees it.
  2. Surv(time) with no event vector — when called with a single positional argument — is interpreted by the survival package as right-censored data with status = 1 for every observation. Every patient is treated as having had a progression event.

Verifying the R semantics in 5 lines:

library(survival)
t <- c(10, 20, 30, 40, 50)
e <- c(1,  0,  1,  0,  1)

buggy   <- Surv(as.numeric(t, e))     # what the paper's code calls
correct <- Surv(t, e)                  # what it should call

buggy            # [1] 10  20  30  40  50      <-- all events observed
correct          # [1] 10  20+ 30  40+ 50      <-- 20 and 40 censored

all(buggy[,"status"] == 1)             # [1] TRUE
all(buggy[,"time"]   == t)             # [1] TRUE

Bug location count. The pattern appears 11 times across the cell-fraction analysis scripts:

$ grep -rn 'Surv(as\.numeric' code/Analysis/ | wc -l
11

All 11 are in lasso_cox_cellFract_tumor_resistanceLASSO_model_PFS.R and lasso_cox_cellFract_stroma_responseLASSO_model_PFS.R — the two scripts that derive and validate the Yale-cohort resistance and response signatures. The remaining (gene-signature, RNA-validation) scripts use the correct two-argument form. So the same author can write Surv(t, e) correctly elsewhere and the broken Surv(as.numeric(t, e)) here.

Effect on claim — numbers (per published Yale headline HR):

  • Resistance signature (Yale tumor, n=32, PFS-2yr): HR 3.8 → 2.58 (point estimate −32%); p 0.004 → 0.053 (13×); significance lost.
  • Response signature (Yale stroma, n=33, PFS-2yr): HR 0.40 → 0.30 (point estimate −25%); p 0.019 → 0.057 (3×); significance lost.
  • Number of patients whose censoring status is silently overwritten by the bug: 13 of 32 Yale tumor patients (40%); 15 of 33 Yale stroma patients (45%). These are the censored observations whose event indicator the bug discards.
  • Repository commit hash at audit time: bug present; PRs/issues: 0; commits since publication: 20; commits referencing the bug: 0. Bug is currently in the published reproduction artifact.

What this isolates. The cell-type cell-fraction signature derivation and its training-set HR computation use the buggy pattern. Reproduction

Self-contained R script (≈40 lines):

library(survival)
library(dplyr)

# Download once:
# git clone https://github.com/tznaung/NSCLC_SpatialOmics
# curl -L https://ndownloader.figshare.com/files/57294182 -o NSCLC.zip
# unzip NSCLC.zip

cellFrac <- read.csv("data/Tumor_Cell_Prop_4.csv", check.names=FALSE)
cellFrac <- cellFrac[cellFrac$TMA == "YTMA_471", ]   # Yale discovery
sig_cols <- c("Proliferating_Tumour", "Granulocytes", "Vessels")
scores      <- rowSums(cellFrac[, sig_cols])
binary_score <- scores >= quantile(scores, 0.66)
df <- data.frame(time         = cellFrac$PFS_2Years_months,
                 event        = cellFrac$PFS_2Years_Index,
                 binary_score = binary_score)
df <- df[complete.cases(df), ]

# Paper's code path:
y_buggy   <- Surv(as.numeric(df$time, df$event))
cox_buggy <- coxph(y_buggy ~ binary_score, data=df)
print(summary(cox_buggy)$conf.int)
print(summary(cox_buggy)$coefficients)

# One-character fix:
y_correct   <- Surv(df$time, df$event)
cox_correct <- coxph(y_correct ~ binary_score, data=df)
print(summary(cox_correct)$conf.int)
print(summary(cox_correct)$coefficients)

Re-run on the stroma response signature is identical, with data/Stroma_Cell_Prop_4.csv and sig_cols <- c("M1_mac","M2_mac","CD4").

Secondary observations

  • LASSO selection of cell types (proliferating tumour / granulocytes / vessels for resistance; M1 / M2 / CD4 for response) was performed against the buggy survival object — so the identity of the selected cell types may differ from what a properly-censored LASSO would pick. But the published Yale HRs above test those three specific cell types directly, so the bug applies to the published number regardless of whether the selection step is also questioned.
  • The published HR=3.8 (1.5–9.1, p=0.004) value appears as a ggplot2::annotate text label at lasso_cox_cellFract_tumor_resistanceLASSO_model_PFS.R:121, computed from the buggy Surv object on the line just above. The number in the published figure caption is derived live from the buggy fit (not hardcoded).
  • Yale cohort size after the TMA == "YTMA_471" restrict: n=32 tumor-compartment samples, n=33 stromal-compartment samples. The abstract mentions n=234 across three cohorts; the Yale discovery slice in the deposited data is much smaller than that count suggests.
  • The bug pattern (11 occurrences in the cell-fraction scripts vs. 0 in the gene-signature scripts) looks like a copy-paste artifact, not malicious data fabrication. The two scripts that contain the bug were almost certainly cloned from a common template.

Why the "wrong uploaded data" defense doesn't apply here

The figshare deposit ships normalized/processed CSVs (Tumor_Cell_Prop_4.csv, Stroma_Cell_Prop_4.csv) that already encode each patient's outcome and cell-type proportions. The Yale cohort restricted-access component (YTMA-471 source images, raw Phenocycler data) is what's behind authorization gates — but the input to the Cox model in the script is the deposited CSV.

Specifically:

  • The deposited CSV is what the script reads (read.csv("Tumor_Cell_Prop_4.csv") at line 13).
  • The bug operates on whatever values the CSV ships — it discards event information regardless of what those values are.
  • The PFS times and event indicators in the CSV (PFS_2Years_months, PFS_2Years_Index) are the exact columns the script names — there is no version mismatch.
  • The buggy and correct versions both run on the deposited CSV. The difference is the one-character fix in the script.

If the authors were to claim the deposited cohort is a subset and the production HR was computed on a larger cohort, they would have to also claim the production code was different — because the same buggy Surv(as.numeric(time, event)) applied to a larger cohort still drops the event column. The buggy code path cannot produce the paper's significance from a larger cohort either, except by the same artifact (treating everyone as a progressor).
