Audit Report — Aung et al., Nature Genetics 2025

This audit was conducted using natural-joints — independent code & data audits of published research papers.

"Spatial signatures for predicting immunotherapy outcomes using multi-omics in non-small cell lung cancer"

Paper: Aung TN, Monkman J, Warrell J, et al. Nat Genet (2025). 10.1038/s41588-025-02351-7 · PMID 41073787 · PMCID PMC12513832.
Code: tznaung/NSCLC_SpatialOmics.
Data: figshare 29944619 (~12 MB) + GEO GSE271689, GSE221733.
Audit date: 2026-06-01.

Headline finding. A Nature Genetics paper claims to predict 2-year PFS in lung-cancer immunotherapy. The training-cohort data says "2 years" is actually 1.45 years.

Of 8 hazard ratios named in the paper's abstract, at least 5 either collapse to non-significance under bug correction, are unreproducible from the released artifact, or are products of post-hoc statistical choices. The paper's central clinical narrative — that the responder signature identifies subgroups outperforming standard-of-care pembrolizumab — collapses to "subgroups that match it" once a single corrupted unit conversion in the deposited Yale Tumor file is corrected.

The spotlight bug: PFS_2Years_months isn't months

Aung et al. 2025 deposits a Yale Tumor CSV with two columns describing time-to-progression: PFS_Days (days from treatment to progression) and PFS_2Years_months (the same time in months, capped at 24).

Compute the implied days-per-month in the file:

mean(PFS_Days / PFS_2Years_months) = 22.11

A real month is 30.44 days (365.25 ÷ 12). The column labeled "months" doesn't hold months — it holds days/22.11. The "2-year cap" at 24 fires at 24 × 22.11 = 530.6 real days = 17.4 real months ≈ 1.45 years.

The paired Stroma file uses the correct 30.44 divisor. Same patients, identical PFS_Days across both files; only the Yale Tumor file is corrupted. The Methods section says twice: "PFS data (time in months and an event indicator)." In the Yale Tumor file, that's false.

The finding's impact

The paper's scientific contribution rests on one claim: the responder signature picks out patient subgroups that outperform standard-of-care immunotherapy — i.e., do better than the ~10-month median PFS of 1L pembrolizumab in NSCLC (KEYNOTE-024).

The bug stretches every Yale Tumor survival time by 37%. Any responder-subgroup median that reads as 12–14 months on the figure is really 8.7–10.2 real months — at or below the SoC benchmark, not above it.

What looked like "the signature identifies durable responders who outperform standard care" becomes "the signature identifies patients who do what pembrolizumab patients already do." A subgroup that just matches SoC is not a clinical contribution.

The Cox HR itself doesn't move (scale-invariant) — the signature still ranks patients. The clinical narrative — "we identify subgroups that beat standard care" — collapses to "we identify subgroups that match it."

And the headline endpoint itself is mislabeled: the paper claims "PFS at 2 years," the IO field's durable-benefit milestone (KEYNOTE-024). The Yale Tumor "2 years" is 1.45 real years. So the signature isn't predicting 2-year PFS at all — it's predicting 17-month PFS, an endpoint that doesn't appear in the clinical literature.

Downstream effects on the Yale Tumor analyses:

  • PFS_2Years_Index — the binary "event by 2 years" flag — is thresholded from this corrupted column. Patients with real events in days 531–730 (between 17.4 and 24 real months) are at risk of being labeled "no event by 2 years" despite progressing before 2 real years.
  • LASSO feature selection is trained against this potentially-mislabeled outcome.
  • Reported Yale Tumor Cox HRs use Surv(_months, _Index).
  • Every Yale Tumor Kaplan-Meier figure plots survival on an x-axis labeled "PFS-2Year (months)" — on the 37%-stretched timescale.
  • The "5-year PFS" landmark in this file is 60 × 22.11 days = 3.6 real years, not 5.

Bugs in the committed code

Surv(as.numeric(time, event)) typo at 11+ sites MAJOR

as.numeric() silently drops extra positional arguments, so the event vector is discarded before Surv() ever sees it; Surv(time) with one argument defaults to "all events observed."

library(survival)
t <- c(10, 20, 30, 40, 50)
e <- c(1,  0,  1,  0,  1)
Surv(as.numeric(t, e))   # 10  20  30  40  50      <-- all events observed
Surv(t, e)               # 10  20+ 30  40+ 50      <-- 20 and 40 censored

Sites: lasso_cox_cellFract_tumor_*.R:20,84,128, lasso_cox_cellFract_stroma_*.R:20,90,138,139, plus 11 sites across the RNA-LASSO scripts. This single bug collapses both Yale headline HRs: Yale tumor resistance HR 3.8 (p=0.004) → 2.58 (p=0.053); Yale stroma response HR 0.4 (p=0.019) → 0.30 (p=0.057). Both 95% CIs cross 1.

BH/FDR correction commented out across all 4 RNA-LASSO scripts MAJOR

In lasso_TrainTest_CK_RNA_*.R:84-85 and 3 sibling scripts:

#FDR <- p.adjust(response$table$PValue, method="BH")
FDR <- response$table$PValue
...
dex_sel_genes = dex_df[which(dex_df$FDR < 0.05),] # take only genes that have FDR < 0.1

The variable named FDR holds the raw edgeR exactTest p-value. The trailing comment also doesn't match the literal threshold. With 6,000–10,000 genes per split gated on raw p < 0.05, ~5% of the genome enters LASSO on chance alone — ~500× more false positives than the paper's "FDR < 0.05" claim implies.

Orphan coefficient files MAJOR

lasso_CK_RNA_neg_..._finalSig.R line 243 writes final_coeffs_PFS_5Years_3celltypes_CW_CK_resistance.csv; line 256 reads final_coeffs_PFS_5Years_3celltypes_CK_resistance_0p1.csv (different filename). A repository-wide search returns zero matches for the read filename. The same pattern affects Yale_firstLine_pre_patients.csv (training cohort definition) and every hzrs_*.csv file. The released code cannot regenerate the published cell-to-gene HRs end-to-end.

Cell-typing per-cell z-score destroys marker discrimination MAJOR

In PCF_Celltyping.ipynb cells 37, 66, 84, 109, each expression matrix is z-scored per cell across markers (axis=1). Cell 86 then applies hardcoded M1 vs M2 gates on those z-scored values at boundary 0.3. Per-cell z-scoring forces every cell to mean-0/SD-1 across its panel — a CD8 cell with high CD8 looks identical to a tumor cell with high pan-CK because both peak in one channel of their normalized panel. Affects all cell labels → cell-fraction features → headline HRs.

Cell-typing ffill priority mislabels Tregs as Proliferating_Tumour MODERATE

The cell-label priority chain: ki67cell > mac_types > gzmbcell > pd1cell > foxp3cell > CD4_types > CT_1. A Ki67+ FOXP3+ CD4 cell (a proliferating Treg) gets labeled Proliferating_Tumour — the lead cell type in the resistance signature. Un-subtyped macrophages default to M1_mac, biasing the M1/M2 ratio toward M1.

Multi-image patient replicates fed to coxph without cluster(Patient_ID) MODERATE

Yale: 3 patients with 2 images each. UQ: 7 patients with 2–3 images each. Replicate cores per patient are fed to coxph as if they were independent observations. Standard errors are too narrow; p-values are too small by ≈10–15%.

Tumor LASSO drops Unidentified + Stroma cell-type columns MODERATE

The slice cellFrac[,c(38:51)] selects 14 cell-type columns but skips Unidentified and Stroma. Row-sums range 0.37–1.0 instead of summing to 1.0. Un-normalized cell-fractions are fed to unstandardized LASSO, biasing feature selection toward features that correlate with how much "non-included" tissue each patient has.

CD8 lineage triple-counted in LASSO MODERATE

CD8_cells, Exhausted CD8, and Cytotoxic CD8 all enter the LASSO design matrix as separate features. Numerically, CD8_cells ≠ Exhausted CD8 + Cytotoxic CD8 (max difference 0.23). The same cells are partially counted across three columns and contribute three independent feature slots, destabilizing selection.

Hardcoded integer column indices in marker-correlation loop MODERATE

annData_protein+Umap_SOmics.R uses expr[,21], expr[,25], expr[,43] for "pdl1", "cd163", "pck" in a correlation loop. A safer pattern (which(colnames(expr) == "PD-L1")) exists in the same file but isn't used here. Any reordering of data.X upstream silently swaps which markers are correlated.

Bugs in the deposited data

PFS_2Years_months = days/22.11 in Yale Tumor file MAJOR

Covered in the spotlight section above. The Yale Tumor file's months column is on a 22.11-day-per-unit scale; the paired Stroma file is correct at 30.44. 37% time-axis stretch on every Yale Tumor figure; "2-year" landmark = 1.45 real years; potential mislabeling of PFS_2Years_Index for patients with events in days 531–730.

Censored ≡ Status ≡ Current Status ≡ OS MODERATE

All three columns are 100% collinear with overall survival in the deposited CSVs:

  • Alive ↔ Censored ↔ Status = 0
  • Deceased ↔ Uncensored ↔ Status = 1

There is no PFS-specific censoring information in these three columns. PFS censoring exists only in the PFS_*Index columns. Any script that pulls a censoring vector from Status silently substitutes OS for PFS.

Yale cohort is n=29–31 unique patients, not n=41 MODERATE

The cell-fraction CSVs contain 32–33 images. After de-duplicating on Patient_ID, the unique-patient count is 29–31 (3 patients are double-imaged). The abstract claims n=41. The (HR, p) values aren't affected — they're computed on n=32 images — but the sample-size claim is materially overstated.

Same patient has different drug across paired files MINOR

Patient 4301 F1 (TS-19 - 0732): ImmunoTx = Nivo in the Stroma file, = Pembro in the Tumor file. Same patient, same image, two files, two drugs.

Same patient has different histology across paired files MINOR

Images 4301 E3, H2, F4: Histology.1 = Adenocarcinoma in the Stroma file, = Adenosquamous in the Tumor file. Same images, two histology labels.

line_at_ITX categorical encoding split by TMA MODERATE

YTMA_471 cohort uses integer "1" for first-line therapy. 4301 cohort uses string "1st line". Biopsy_at_ITX is missing for the entire 4301 cohort, making it a perfect cohort indicator masquerading as a biology variable.

Patient vital-status flips across duplicate cores MINOR

Patient 88 is coded simultaneously Deceased and Alive across duplicate cores at the same OS_Days=137. Patient 9 has the same flip. Patient TS-19-0109 has Response flipping between Responder and Non-responder across 3 cores. These affect ≤2 patients in a 29-patient Yale cohort but reveal cores were not de-duplicated before label assignment.

Cross-file row-count and ID drift MINOR

Tumor file has 67 rows; Stroma file has 68. Five image IDs are unique to one or the other. UQ_CK vs UQ_Stroma validation cohorts overlap on only 21 of 30/27 PatIDs. PFS_5Years_months disagrees at the second decimal across shared rows (1.80 vs 1.84). Cross-cohort exact-match joins fail silently.

Inconsistent free-text histology labels MINOR

The Histology column contains Squamous vs squamous cell carcinoma vs Squamous cell carcinoma, plus one label with an embedded newline (\n) in the middle. Any filter or grouping on this column produces inconsistent cohorts depending on which spelling is matched.

Choices that overstate the significance

Cell-to-gene signatures selected by held-out test-cohort HR MAJOR

In lasso_CK_RNA_neg_..._finalSig.R:52:

hzrs = read.csv("hzrs_CK_PFS_5Years_3celltypes_resistance_P_G_V_CW_genes.csv")
good_models = which((hzrs$x) >= 1.5)         # resistance direction
# mirror in stroma response script:
good_models = which((hzrs$x) <= 0.7)         # response direction

hzrs$x is the held-out test-cohort HR from 50 random 80/20 splits. The final signature is built by running gene voting only over splits whose test HR was already in the desired direction. The validation result is the model-selection criterion — textbook circular validation. Genes appearing across these "good" splits are then assembled and re-evaluated on the same Yale cohort.

UQ validation p-values halved 1-sided post-hoc MAJOR

In 4 validation scripts:

p_value_one_sided <- ifelse(summary(cox)$coefficients[2] > 1,
                            p_value_two_sided / 2,
                            1 - p_value_two_sided / 2)

Direction is picked post-hoc from the sign of the observed coefficient. Plots annotate this with "Log-Rank-1-sided" for validation and "Log-Rank-2-sided" for discovery. Both abstract validation p-values become two-sided 0.10 (UQ tumor) and 0.072 (UQ stroma) — neither below conventional significance, both 95% CIs cross 1.

Tumor and Stroma analyses share 28+ patients — not 8 independent tests MAJOR

Yale tumor (29 patients) ∩ Yale stroma (31 patients) = 28 in common. UQ tumor (26) ∩ UQ stroma (26) = 26 (full overlap). The 4 cell-type HRs + 4 cell-to-gene HRs the abstract presents as "8 consistent results" are not 8 independent tests — most are recomputations on substantially the same patients with different feature transformations. Bonferroni at family size 8 (α=0.0062) drops every reported p-value except Yale tumor (0.004) and Yale cell-to-gene resistance (0.002) below significance — and both survivors are in-sample LASSO refits.

lower.limits=0 / upper.limits=0 forces directional signatures MAJOR

The LASSO sign constraint lower.limits = 0 (tumor) and upper.limits = 0 (stroma) guarantees the resulting signature is non-negative ("resistance") or non-positive ("response") — direction is set by a keyword, not by the data. Post-LASSO refit then silently drops coefficients via coeffs = coeffs[which(coeffs >= 2)] (HR ≥ 7.4 per unit fraction), a hardcoded filter with no rationale. With correct Surv + sign constraint, Yale tumor signature gives HR=2.18, p=0.105. Without sign constraint, no cell type meets the stability threshold.

Cohort-comparability gap: Yale = 1st-line pre-Tx Pembro; UQ = post-1st-line Nivo MAJOR

Yale training: all Biopsy_at_ITX = "Pre", all line_at_ITX = "1", 28/32 on Pembrolizumab. UQ validation: Biopsy_at_ITX = #N/A for 35/35, 27/35 on Nivolumab, 23/35 ≥ 2nd line. Pre-treatment vs post-treatment biopsies are biologically different — clonal selection under IO. The commented-out filters in the LASSO scripts (Histology %in% c("Squamous"), ImmunoTx %in% c("Nivo")) reveal the authors are aware these are confounders.

No clinical covariate adjustment MODERATE

Final reported HRs are univariate Cox — no age, smoking, histology, line of therapy, drug, or biopsy timing. Standard practice in IO biomarker studies includes at least line and drug as covariates.

LASSO fit on PFS_5Years, headline HR reported on PFS_2Years MODERATE

Same author, same script. The cell-to-gene pipeline also fits gene selection on PFS_5Years (lasso_CK_RNA_neg_..._finalSig.R:274) but reports a training HR on OS_5Years — three different endpoints in one script. Pick-best-endpoint flexibility.

Data-dependent tertile cutpoint computed on test cohort MINOR

The "tertile" cutpoint for binarizing the signature score is computed from the test cohort's own score distribution — a mild form of test-set leakage where the dichotomization boundary depends on the test data.

Inconsistent LASSO stability thresholds MINOR

Tumor LASSO: 100 random seeds, 50% stability threshold for retaining a feature. Stroma LASSO: 50 seeds, 30% threshold. Different stringency for the two compartments; appears tuned to land on a reportable signature in each.

Reproducibility gaps

Greek validation cohort entirely absent from the repo MAJOR

A repository-wide search for greek|hellenic|patras|athens|thessaloniki|crete returns zero matches in any analysis script. The abstract's Greek validation HRs (resistance HR=1.7, response HR=0.56, n=79) are not reproducible from the public artifact. The third "independent" cohort exists only in manuscript text.

UQ stroma RNA released code emits HR=1.1, p=0.6 — abstract claims HR=0.38 MAJOR

validate_finalSigs_pStroma_RNA.R:157 contains the literal label:

label = "HR = 1.1 (0.43-3) \n p = 0.6 (Log-Rank-1-sided) \n cutpoint = tertile"

The script uses Surv(OS_5Years_months, OS_5Years_index) on the UQ_Stroma CSV. Output: HR=1.1, p=0.6. Abstract reports HR=0.38 for the same comparison. The released code does not reproduce the abstract's UQ stroma response HR. (A two-sided p of 0.6 is symmetric — this is not a sidedness artifact, the script computes HR=1.1.)

Three deposit files referenced by released code don't exist MAJOR

  • Yale_firstLine_pre_patients.csv — defines the Yale training cohort
  • final_coeffs_PFS_5Years_3celltypes_*_resistance_0p1.csv — read by signature scripts (different filename than what gets written)
  • hzrs_CK_PFS_5Years_3celltypes_resistance_P_G_V_CW_genes.csv and other hzrs_*.csv — held-out test-cohort HRs from 50 train/test splits

The published cell-to-gene HR=5.1 cannot be regenerated from the artifacts the paper points readers to.
